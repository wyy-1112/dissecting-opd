# Mechanism analysis

Minimal scripts for the three measurements of the paper. `reference_results/` holds the outputs the paper
numbers were read from (small JSON/CSV only; score tensors and top-K supports can be recomputed).

Notation: θ₀ Initial student, θ_T teacher (same architecture), θ_D an OPD endpoint. Task vectors
Δ_T = θ_T − θ₀, Δ_D = θ_D − θ₀.

## 1. Parameter displacement — `parameter/`

- `hf_task_vector_cosine.py --base θ₀ --endpoint LABEL=PATH ... --pair A,B`
  Reads HF safetensors, promotes every tensor to FP32, accumulates Gram entries in FP64, all tensors in the
  weight map. Outputs `norms` (‖Δ‖) and `cosines` (cos(Δ_A, Δ_B)). Used for the parameter axis of the
  parameter-vs-function scatter, where both axes must read the same published HF weights.
- `fsdp_task_vector_cosine.py --base θ₀ --endpoint LABEL=<run>/global_step_N/actor ...`
  Reconstructs the FP32 optimizer-master weights from native FSDP shards (never the bf16 merger output),
  excludes only the tied `lm_head.weight` alias, reports global and per-layer cosines (`exact_norms`,
  `exact_cosines`). Pass `--expected-parameter-count 0` (the default count is for 1.7B models).
  Paper runs used `--dot-product-mode gram-fp32`.
- `task_vector_distance.py <json> [--reference LABEL]` adds, from either output,
  ‖Δ_A − Δ_B‖ = √(‖Δ_A‖² + ‖Δ_B‖² − 2‖Δ_A‖‖Δ_B‖cos), the distance relative to ‖Δ_ref‖ and the scalar
  projection ⟨Δ_A, Δ_ref⟩ / ‖Δ_ref‖².

The two tools answer different questions (published bf16/HF weights vs optimizer FP32 masters) and are
not mixed within one comparison.

## 2. Functional change — `functional/`

All models are scored on the same frozen states (prompt + Initial-generated prefix tokens, stored as token
ids; no retokenization at scoring time):

```bash
P=data/probes/qwen3_4b
# top-K support of the Initial model on the frozen states
python functional/probe_scores.py fisher-base --cohort $P/cohort.jsonl --manifest $P/manifest.json \
    --checkpoint $MODEL_ROOT/qwen3_4b --top-k 128 --output base_topk.npz
# log-probs of any model on that support (repeat per model: Initial in FP32, teacher, endpoints)
python functional/probe_scores.py fisher-score --cohort $P/cohort.jsonl --manifest $P/manifest.json \
    --reference base_topk.npz --checkpoint <model> --label <label> --output <label>.npz \
    --dtype float32 --attn-implementation sdpa --logit-chunk-tokens 64
# direction similarity and scalar fits against a reference label
python functional/functional_cosine.py --reference base_topk.npz --score teacher=teacher.npz \
    --score <label>=<label>.npz ... --reference-label teacher --anchor-base-score base_fp32=base_fp32.npz \
    --output collinearity.json
# teacher-relative KL and gap closed
python functional/functional_kl.py --reference base_topk.npz --score ... \
    --teacher-label teacher --anchor-base-score base_fp32=base_fp32.npz --output influence.json
```

At each state, S = the K = 128 most likely tokens under θ₀ (full-vocabulary softmax), p₀ = θ₀
probabilities, q₀ = p₀ renormalized on S:

- d_θ(i) = log p_θ(i) − log p₀(i),  d̄_θ = Σ_{i∈S} q₀(i) d_θ(i)
- functional change vector v_θ(i) = √p₀(i) · (d_θ(i) − d̄_θ)  (Fisher-weighted, centered)
- direction similarity cos(v_A, v_B) over all (state × token) components of a domain; the `all` value
  concatenates the four domains (it is not a mean of domain cosines). Scalar fit α = ⟨v_D, v_ref⟩ / ‖v_ref‖².
- KL: q_θ = p_θ renormalized on S; L_j(θ) = mean over positions of probe j of KL(q_T ‖ q_θ);
  gap closed = Σ_j w_j (L_j(θ₀) − L_j(θ)) / Σ_j w_j L_j(θ₀), w_j = token count of probe j. Mass outside S
  is excluded.

Endpoints are scored from merged HF weights in FP32; the Initial reference uses an FP32 score of θ₀
(`--anchor-base-score`).

**Reference model.** `--reference-label` selects v_ref. For teacher alignment it is the teacher. When an
endpoint is compared with another OPD endpoint, the reference is that endpoint's own checkpoint, and the
training budget must match what is being compared: e.g. for a 15+15-step support switch the native
comparison is the 30-step continuation on the same support, not the 15-step endpoint; the two are
different checkpoints and appear as different labels.

## 3. Fixed probes — `probes/`, `data/probes/`

`probe_scores.py build` freezes a probe cohort: per domain (Math, GPQA-Diamond, HumanEval+,
LiveCodeBench v6) 32 trajectories, candidates ranked by SHA-256 of `seed\0domain\0source_id` (distinct
prompts first), response truncated to 1,024 tokens, sequence ≤ 2,048 tokens. Prefixes are generated by
the Initial student, never by the teacher or an endpoint:

- Math: `probes/sample_math_prefixes.py` samples the Initial student on 96 prompts × 8 samples
  (seed 20260821, 8,192 tokens) from the DeepMath 3840 schedule (`data/probes/qwen3_4b_math_prefixes`);
  for the other families the Initial model's own math-eval generations.
- GPQA / HumanEval+ / LCB: the first stored sample of each selected task from the Initial model's OOD eval.

| `data/probes/` | Initial model | positions |
|---|---|---|
| `qwen3_4b` | Qwen3-4B (Math GRPO-500, Code GRPO-300, 30B→4B) | 73,823 |
| `r1_distill_1p5b` | DeepSeek-R1-Distill-Qwen-1.5B (JustRL, DeepScaleR) | 130,882 |
| `r1_distill_1p5b_nemotron` | DeepSeek-R1-Distill-Qwen-1.5B (Nemotron) | 130,663 |
| `r1_distill_7b` | DeepSeek-R1-Distill-Qwen-7B (Light-R1) | 130,414 |
| `qwen3_4b_instruct` | Qwen3-4B-Instruct-2507 (Inst-Mix) | 95,216 |

Each `manifest.json` records the base checkpoint fingerprint, tokenizer hash, selection parameters and
source files.

## Reference results

- `reference_results/scatter/`: parameter vs functional cosine, 43 same-checkpoint points
  (`scatter_data.csv`, README with definitions and caveats).
- `reference_results/functional/`: collinearity / influence JSONs per family (their `inputs` blocks list the
  exact score files, labels and cohort hashes).
- `reference_results/parameter/`: same-HF parameter cosines per family.
